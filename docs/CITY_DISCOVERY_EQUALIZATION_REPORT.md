# City discovery equalization — implementation report

Completed 2026-10-06. Scope: /fr, /ar, /fr/cities, /ar/cities only. No Git commands, push or deployment.

1. **Previous hierarchy:** LandingCityPreview explicitly filtered to Casablanca, used max-w-2xl and a hard-coded available badge. The directory rendered CasablancaSpotlight as a large horizontal feature before a CityExplorer collection that explicitly excluded Casablanca. The landing heading also described Casablanca as the opening city.
2. **Special cases removed:** The landing slug filter, oversized single-card container, hard-coded badge, directory exclusion and standalone spotlight were removed. The unused CasablancaSpotlight component was deleted, including its private status fetch. The two localized landing headings now invite discovery of all territories.
3. **Files changed:** components/city/CityCard.tsx (added), components/city/CityExplorer.tsx, components/city/CasablancaSpotlight.tsx (deleted), components/landing/NationalLandingSections.tsx, app/[locale]/cities/page.tsx, lib/cities/registry.ts, messages/fr.json, messages/ar.json, tests/frontend/city-discovery.test.ts (added). Evidence added: this report, reports/city-discovery-qa.json, reports/city-discovery-directory.png, reports/city-discovery-landing.png. Build/type caches refreshed normally.
4. **Landing:** All three published cities appear in one balanced grid, with each city's own existing first gallery image, localized region, estimation badge and city-detail link. Existing marketing sections and national hero remain intact.
5. **Directory:** Search/filter panel followed by one consistent grid containing all published cities. No standalone featured city remains.
6. **Shared architecture:** CityCard and CityCardGrid are shared by landing and CityExplorer. Identical 16:10 imagery, type sizes, card radius, borders, shadows, image zoom, hover movement, focus treatment, badge placement and bottom discovery CTA. Badge is on its own row to avoid squeezing long city/region labels. Auto-equal grid rows and flex content preserve equivalent heights across rows.
7. **Ordering:** getPublicCities filters publicVisible from CITY_REGISTRY while preserving its explicit existing catalog array order: Casablanca, Rabat, Marrakech. No duplicate ranking or ordering field introduced. Future published cities join automatically. Config calls the publication gate cityPage.publicVisible; estimation and market have their own publicEnabled gates.
8. **Capability inconsistency:** The landing hard-coded availability, while CasablancaSpotlight privately fetched /api/ml/metadata and treated non-OK/network responses as a model outage. That endpoint has no route in this application. The failed request therefore produced a false suspended message unrelated to the published registry or inference state.
9. **Source of truth:** Discovery now uses city.estimation.publicEnabled from CITY_REGISTRY, exactly as existing city hero badges, CityCapabilityActions, CityServicesSection and publicNavigationEstimation do. Casablanca is enabled; Rabat/Marrakech are disabled and display coming-soon labels. Market gates remain enabled only for Casablanca. Legacy national coverage flags and modelRef are not used as capability signals. No service state is inferred from a missing metadata endpoint. Registry publication describes activated services; genuine inference failures retain existing API handling. This refactor does not claim continuous remote gateway health monitoring. The real approved Casablanca model/API tests pass.
10. **French:** All three cities and correct regions/status labels render on both surfaces. Territorial heading no longer privileges Casablanca.
11. **Arabic:** Both surfaces use Arabic city/region/status/discovery labels, document dir=rtl, mirrored catalog positions and leftward CTA arrows. No clipped badges or overflow observed. Existing shared branding/control labels were preserved.
12. **Desktop:** At 1440px, three columns. Every card is 392px wide and 440px high in FR, 439px high in AR; image height 244px. All three sizes match within each surface/theme/locale.
13. **Tablet:** At 820px, two columns. Every card is 372px wide and 427.5px high in FR, 426.5px in AR; images 231.5px high. The third card retains the same width/height.
14. **Mobile:** At 390px, one column. Every card is approximately 350.4px wide and 414px high in FR, 413px in AR; images 218px high. Whole-card links provide generous touch targets. No horizontal page overflow in any of the 24 viewport/route/theme checks.
15. **Light:** Tested all four routes at desktop/tablet/mobile using existing surface/text/border/status tokens. Equivalent hierarchy and legible labels.
16. **Dark:** Same 12 route/viewport checks passed. Screenshots include dark desktop landing/directory and visual inspection of Arabic mobile. No new fixed city colors introduced. Hover and focus share the same treatment.

All cards use the existing common filtering system. Search aliases retain Arabic/accent support. Empty-state and filter UI retained.

Existing automated exact-markup hashes for Casablanca/Rabat city and market bodies pass in FR/AR. No detail renderer, editorial, media config/assets, Market/GeoJSON, estimator, inference/models, auth/security/database code changed. Existing auth, entitlement, RLS and navigation regressions pass.
